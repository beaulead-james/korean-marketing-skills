# 출력 형식

모든 스킬이 이 계약을 따라요. 짧게 둔 이유가 있어요. 계약은 네 섹션, 선택이 있을 때의 Quick Pick, 콕 집은 요청의 퀵 모드, 아래의 산출물 위생이에요. 나머지는 절제예요.

---

## 원칙

1. **마크다운이 기본이에요.** Claude Code가 마크다운을 렌더하고, Notion, Slack 내보내기, 산출물이 닿는 편집기도 그래요. 제목, 굵은 라벨, 표, 목록을 써요. 유니코드 상자, 아스키 구분선, 고정 줄 너비는 쓰지 마세요. 고정폭 글꼴이어야 예뻐 보이는 출력은 다른 곳에서는 깨져요.

2. **파일이 먼저, 출력이 다음이에요.** 산출물은 채팅 요약 전에 디스크 (`./brand/`, `./campaigns/<name>/`)에 살아요. 긴 내용 (전문, 시퀀스 전체, 상세 브리프)은 파일에 두고, 채팅은 저장된 것, 핵심 결정, 다음 경로를 보여요. 에셋마다 `./brand/assets.md`에 한 줄을 붙여요. 퀵 모드는 이것을 건너뛰고, 일회성 에셋을 위해 `./brand/`를 만들지 않아요.

3. **5초 안에 훑혀요.** 산출물 이름, 추천, 다음 단계가 스크롤이나 사냥 없이 보여요. 예측 가능한 섹션 순서가 그 일의 대부분을 해요.

4. **전문가의 절제.** 이모지 없음. 느낌표 없음. "좋은 소식입니다" 같은 채움 없음. 서두 ("여기 있습니다", "만들었습니다") 없음. 출력은 헤더에서 시작해요. 출력이 산출물이에요. 제시하고 다음으로 가요.

5. **추천이 바로 보여요.** 선택지가 여럿이면 추천이 먼저 (Quick Pick), 세부가 다음이에요.

6. **클라이언트는 작업을 읽고, 과정을 읽지 않아요.** 에이전트가 거기 도달하려고 한 일은 산출물 밖에 있어요. 산출물 위생을 보세요.

---

## 네 섹션 계약

모든 스킬 출력은 이 섹션을 이 순서로 가져요. 정말 해당 없으면 (드물어요) 왜 그런지 한 줄과 함께 포함해요.

### 1. 헤더

```markdown
## 랜딩 카피: 봄 프로모션
2026-06-10 · 봄 설비 프로모션용
```

`##` 제목은 산출물 이름 (스킬 이름이 아님)이에요. 그다음 한 줄은 날짜와 용도. 어떤 브랜드 파일, 각도, 모드, 도구가 이 실행을 만들었는지는 적지 마세요.

### 2. 내용

산출물 요약, 또는 짧으면 산출물 자체. 그다음 짧은 "출처와 가정" 노트 (산출물 위생). 깨끗한 마크다운.

- 구조는 제목, 라벨은 굵게, 항목은 목록.
- 표는 정말로 열거할 사실 (키워드 지표, 발송 일정, 변형 비교)에만. 한 열짜리 상태 목록에 쓰지 말고, 같은 표를 두 번 내지 마세요.
- 추정 숫자에는 `~`. 조각 전체의 데이터 품질은 노트에 한 번, 평범한 말로. 줄마다 태그로 달지 마세요. 돈은 원이에요. 예시 숫자는 예시라고 표시해요.

### 3. 저장한 파일

```markdown
**저장한 파일:**
- ./campaigns/spring-launch/landing-page.md (new)
- ./brand/positioning.md (updated)
- ./brand/assets.md (1 entry appended)
```

정확한 상대 경로와 `(new)` / `(updated)` / `(n entries appended)`. 파일을 쓰는 스킬은 무엇을 썼는지 보여요. 사용자가 출력을 찾아다니지 않아요. 아무것도 안 썼으면 (분석만) `No files written (analysis-only output).`라고 해요.

### 4. 다음

```markdown
**다음:**
- /email-sequences: 이 페이지를 환영 시퀀스 5통으로 (~15분)
- /creative: 크리에이티브 키트가 연결된 경우, 페이지 히어로 (~10분)
- /content-atomizer: 우선 플랫폼 2곳에 퍼뜨리기 (~10분)

지금 하는 일을 말해 주시면 경로를 잡아 드릴게요.
```

구체적인 `/skill` 제안 2개에서 4개. 각각 이유와 대략의 시간. 라우팅 폴백 한 줄로 끝내요. 워크플로가 여기서 끝나면 그렇게 말하고 `/start-here` 상태 검토를 가리켜요. 저장한 파일과 다음은 산출물 다음에 있어요. 저장된 파일 자체에는 스킬 이름이나 다음 스킬 라우팅을 넣지 마세요.

**/creative 제안은 조건부예요.** 둘 다 참일 때만 시각 제작 단계를 제안해요. Replicate가 연결됨 (`.env` 또는 stack.md에 키) AND 그 에셋이 시각에서 이득 (랜딩 히어로, 광고 크리에이티브, 소셜 그래픽. 키워드 계획이나 이메일 시퀀스는 아님). 제안되면 목록의 선택이지, 자동으로 다음 단계가 아니에요.

이 팩은 유료 제안으로 보내지 않아요. 다음에 작성자 팀, 커뮤니티, 하우스 툴 구매를 붙이지 마세요.

## 산출물 위생

클라이언트 산출물에는 작업만 있어요. 완성된 카피, 페이지, 계획, 다음 단계. 클라이언트가 쓸 순서예요. 완성품이 먼저 (페이지, 메시지, 광고), 그다음 운영 계획, 그다음 다음 단계. 과정은 밖에 있어요.

**산출물에 보여 주지 마세요.**

- 스크립트 경로 (`${CLAUDE_SKILL_DIR}/...`, `start-here/scripts/...`)나 에이전트가 실행한 명령.
- 작업을 만들려고 쓴 도구, 스킬, 커넥터, 능력 티어의 이름 ("이 경로로", "강화 티어", "Firecrawl 실행"). 클라이언트가 사거나 써야 하는 도구를 계획 안의 추천으로 말하는 것은 괜찮아요.
- 자기 점수, 루브릭, 품질 표, 점수 이력, 통과/실패 체크리스트.
- 내부 데이터 라벨 장부: 줄이나 행의 `Data: ...` 태그, 증거 id, 출처 품질 코드.
- "매트릭스 상태", 셀 id와 채움 상태, 원장, 워터마크, 라우팅 영수증, 어떤 브랜드 파일을 불러왔다는 줄.

**품질 점검은 조용히 돌려요.** 채점하고, 약한 부분을 찾고, 다시 쓰고, 다시 채점하는 것은 내부 단계예요. 통과한 작업만 보여요. 고칠 수 없는 약점은 노트에 한 줄.

**출처와 가정.** 증거와 가정은 내용 끝의 짧은 노트, 최대 10줄. 작업이 무엇에 기대는지 (출처와 날짜를 한 문장에), 데이터 품질을 평범한 말로, 클라이언트가 확인할 것, 빠진 것. 작업을 바꾼 학습은 바꿨을 때만 한 줄. 저장된 점검이 돌았으면 (`taste-loop.md`) 한 줄 가능 ("저장된 점검 9개와 맞춰 봤어요."). SEO와 AI 검색 스킬의 갭 영수증 (무엇을 확인했고, 무엇을 못 했고, 다음을 여는 것)은 그 줄 가운데 최대 3줄. 더 길면 작업 파일로.

**작업 파일.** 증거 묶음, 주장별 출처, 점수 이력, 도구와 라우팅 출력, 매트릭스 장부는 `./campaigns/<name>/notes.md`나 해당 브랜드 파일에 있어요. 저장하고, 붙여 넣지 마세요. 저장한 파일 목록은 그것들을 최대 한 번 이름만 적어요.

**플레이스홀더나 빠진 입력은 한 줄.** 무엇이 빠졌는지 말해요 ("도메인이 없어서 DNS와 수신 확인은 하지 않았어요"). 플레이스홀더 (yourdomain.com, [사업자명], example.com)를 길게 감사하거나, 그것에 대해 점검을 돌리지 마세요.

**한 가지만 한 번.** 표 중복, 본문을 반복하는 요약, 채팅이 이미 보여 준 것이나 파일이 이미 가진 것의 재진술 없음.

**일 종류별 분량.**

| 일 | 분량 |
|---|---|
| 페이지, 랜딩 | 카피 약 800에서 1,500단어 |
| 계획 | 약 1,200에서 2,500단어 |
| 이메일·문자·알림톡 시퀀스 | 메시지와 노트 200단어 |
| 광고 세트 | 광고와 짧은 테스트 계획 |

요청이 더 많은 조각을 명시할 때만 늘려요. 추가 조각 없이 분량을 넘으면 자르세요. 과정부터, 작업이 아닌 것부터.

## Quick Pick

스킬이 여러 선택 (각도, 콘셉트, 헤드라인 변형)을 낼 때, 추천은 상세 옵션 앞에 와요.

```markdown
**Quick Pick: ★ 2번: 질문 훅**
"견적서가 한 장인데, 왜 답은 안 올까요?"
맞는 곳: 처음 보는 사람, 의심 많은 구매자. 아래가 모든 선택.
```

★ 하나, 전체 목록에서 찾을 옵션 번호, 한 줄 이유나 카피 발췌. 확실한 승자가 없으면 블록을 생략해요. 추천을 지어내지 마세요.

## 퀵 모드

사용자가 에셋 하나를 콕 집으면 ("이 주제로 링크드인 글", "제목 5개", "제품 사진") 의식을 건너뛰고 전달해요.

- 프로젝트 상태 스캔, 다단계 워크플로 제안, 갭 분석, 빠진 파일 경고 없음.
- 에셋만 (파일 먼저 원칙으로 디스크에 저장), 그다음 다음 한 줄.

**퀵 모드가 "먼저 스캔" 규칙을 이겨요.** 스킬 자신의 지시가 생성 전에 컨텍스트를 감사하고, 계획을 제안하고, 브랜드 파운데이션을 확인하라고 해도, 콕 집은 단일 에셋 요청은 그것을 덮어요. 먼저 전달해요.

**퀵 모드가 아닌 것:** "도와주세요", "어디서 시작하죠", "설정해 주세요". 탐색은 전체 경험이에요.

## 상태 표시

내용 섹션 안에서 아껴 쓰는 표시 셋.

| 표시 | 뜻 |
|------|---------|
| ✓ | 있음 / 통과 / 저장됨 |
| ✗ | 없음 / 실패 |
| ★ | 추천 |

팔레트는 이것뿐이에요. 진행 스피너, 원 숫자, 별점 행, 트리 글리프 없음. 상태 표시가 에이전트가 확인한 것의 상태 표가 되면 안 돼요.

## 안티 패턴

- **상자나 구분선 그림 없음.** 박스 드로잉 문자, 가로줄 장식, 트리 글리프, 원 숫자 없음. 마크다운 제목, 목록, 번호 목록.
- **글자 수 세지 않음.** 고정 줄 너비, 공백으로 맞춘 열, 들여쓰기 도표 없음. 보통 마크다운을 쓰고 렌더러에 맡기세요.
- **서두 없음, 후기 없음.** 헤더에서 시작하고, 다음에서 끝내요.
- **이모지 없음.** 출력 어디에도.
- **산출물을 채팅에 쏟지 않음.** 2,000단어 글을 채팅에 붙여 넣는 것은, 저장되어 있어도 버그예요. `./campaigns/`에 저장하세요.
- **고아 출력 없음.** 저장한 파일이나 다음이 없으면 버그예요.
- **과정 유출 없음.** 산출물 안의 스크립트 경로, 점수 표, 줄마다 다는 데이터 태그, 도구나 티어 이름, 매트릭스 상태는 버그예요.
- **지어낸 지표 없음.** 숫자가 필요한 예시는 예시라고 표시해요 ("예시: 2.1%"). 추정에는 `~`, 출처와 가정 노트가 어디서 왔는지 말해요. 영어권 웹의 인용 통계를 네이버 사실처럼 쓰지 마세요.

## 완성 예시 (출력 모양)

```markdown
## 제목 변형: 환영 메시지 1
2026-06-10 · 환영 시퀀스용

**Quick Pick: ★ 1번: 증거 + 구체**
"이 견적 양식으로 상담 3건을 잡았어요"

1. ★ "이 견적 양식으로 상담 3건을 잡았어요", 증거 + 구체
2. "견적서가 안 읽히면, 이 한 장을 보세요", 호기심 + 패턴 끊기
3. "전화가 오는 3통 시퀀스", 쓸모, 가치가 분명

추천 A/B: 1 대 2. 승부는 클릭, 답장, 예약으로 봐요. 오픈율로 보지 마세요.
위 3건은 예시예요. 이 사업의 실제 숫자가 아니면 산출물에 사실처럼 두지 마세요.

**출처와 가정:**
- 과거 발송과 현재 보이스 노트에서 썼어요. 라이브 리서치는 없어요.
- 5월에 이 리스트는 질문형 제목이 증거형보다 낮아서, 1번이 앞이에요.

**저장한 파일:**
- ./campaigns/welcome-flow/subject-lines.md (new)
- ./brand/assets.md (1 entry appended)

**다음:**
- /email-sequences: 이긴 제목 뒤의 본문 (~10분)

지금 하는 일을 말해 주시면 경로를 잡아 드릴게요.
```
