# 워크플로: 풀 퍼널 빌드

한 제안에 랜딩, 리드 마그넷, 환영 시퀀스, 런칭 콘텐츠, 유료 매체 브리프가 함께 필요할 때 쓰는 온디맨드 워크플로예요. 기존 스킬 위의 오케스트레이션이지, 그 판단을 대체하지 않아요. 모든 것은 `./campaigns/<campaign-slug>/` 아래 초안이에요. 배포, 발송, ESP 푸시, 광고 플랫폼 제출은 없어요.

메시지 기본은 카카오 알림톡 (정보성), 친구톡 (광고성), 문자, 그다음 이메일이에요. 광고성 문안은 (광고), 보내는 이, 수신거부를 갖춰요. 야간 21:00~08:00 광고는 별도 동의가 있을 때만 계획해요.

## 워크플로 지도

| 단계 | 일 | 완료 규칙 |
|---|---|---|
| 0 | `/positioning-angles`, 그다음 `/lead-magnet` 콘셉트 선택 | 사용자가 각도 하나와 마그넷 콘셉트 하나를 승인 |
| 1, 병렬 | `/direct-response-copy`, `/lead-magnet` BUILD, `/email-sequences` | 각 가지가 초안을 쓰거나 갭을 기록 |
| 2, 병렬 | `/landing-page` BUILD FROM COPY, `/content-atomizer`, `/paid-ads` CAMPAIGN BUILD | 각 가지가 1단계의 실제 에셋을 씀. 플레이스홀더 금지 |
| 3 | 통합과 QA 게이트 | 정직한 캠페인 보고서 하나와 사람이 라이브로 올리는 체크리스트 |

0단계만 결정 지점이에요. 각도와 콘셉트가 정해지면 병렬 가지는 문서화된 기본값을 쓰고 더 묻지 않아요. 실패한 가지는 보고서의 갭으로 남고, 관계없는 작업을 멈추지 않아요.

## 프롬프트

칸을 채운 다음 마케팅 워크스페이스에 붙여 넣어요.

```
풀 퍼널을 만든다. 제안: <한 문장>. 캠페인 슬러그: <campaign-slug>.

너는 오케스트레이터다. 모든 가지 전에 활성 브랜드 컨텍스트를 읽고 그 제약을 유지한다. 모든 출력은 ./campaigns/<campaign-slug>/ 아래이고 사람 검토용 DRAFT다. 배포, 발송, 게시, 예약, 업로드, 지출은 하지 않는다. 유료 상품으로 연결하는 문장을 붙이지 않는다.

0단계. 내가 있는 자리에서 일한다. 이 제안으로 /positioning-angles를 실행하고 추천 각도를 보여 준다. 내가 각도 하나를 승인한 뒤에만 /lead-magnet의 콘셉트 선택 단계를 실행하고 콘셉트 하나를 고르게 한다. 승인된 포지셔닝을 저장하고 ./campaigns/<campaign-slug>/ad-matrix.md와 ad-matrix.json을 쓴다.

1단계. 세 작업 흐름을 병렬로 보낸다. 각각에 승인된 각도, 승인된 마그넷 콘셉트, 관련 브랜드 컨텍스트, 자신의 SKILL.md를 준다.
1. /direct-response-copy: 채점과 다시 쓰기 루프로 랜딩 카피를 초안하고, 승인된 카피 경로와 /landing-page 인계 컨텍스트를 남긴다.
2. /lead-magnet BUILD: 선택한 리드 마그넷을 캠페인 디렉터리에 만든다.
3. /email-sequences: 마그넷에서 제안으로 가는 환영 시퀀스를 초안한다. 채널은 알림톡, 친구톡, 문자, 이메일 순으로 판단한다. 수신 사전 점검 결과를 보고하고 ESP에는 푸시하지 않는다.
셋을 기다린다. 실패는 기록하고 쓸 수 있는 가지로 계속한다.

2단계. 세 작업 흐름을 병렬로 보낸다.
4. /landing-page BUILD FROM COPY: 1단계의 승인된 카피 경로, 인지 수준, 변형으로 ./campaigns/<campaign-slug>/page/ 아래 페이지를 만든다. 렌더와 QA는 하되 배포하지 않는다. 첫 화면에 하는 일, 지역, 약속, 전화·카카오·예약이 보이게 한다.
5. /content-atomizer: 완성된 페이지 카피와 마그넷을 브랜드가 실제로 운영하는 플랫폼에 맞춘다. 초안은 ./campaigns/<campaign-slug>/social/ 아래. 네이버 블로그, 인스타그램, 스레드, 유튜브 쇼츠가 기본 후보이다.
6. /paid-ads CAMPAIGN BUILD: 승인된 광고 매트릭스와 실제 마그넷 훅으로 캠페인 카피와 크리에이티브 브리프를 만든다. 브리프만. 아무것도 런칭하지 않는다. 네이버 파워링크와 플레이스 광고를 계정이 있는 메타·구글보다 먼저 판단한다.
셋을 기다린다.

3단계. QA 게이트와 보고. 만든 파일마다 그 스킬이 말한 품질 게이트와 맞춘다. 보고된 점수는 그대로 보존하고, 증거는 Data: LIVE, LOCAL DOCS, 또는 MODEL KNOWLEDGE로 표시하고, 빠지거나 기준 아래인 작업은 끝없이 고치지 말고 NEEDS HUMAN으로 표시한다. ./campaigns/<campaign-slug>/campaign-report.md에 파일 목록, 점수와 갭, 퍼널 지도, 사람이 라이브로 올리는 체크리스트, /performance-review 측정 후속을 쓴다. brand.yaml에 캠페인 계획을 표시하고, 아직 등록되지 않은 산출물에만 assets.md 행을 덧붙인다. _system/output-format.md의 요약 형식으로 끝낸다.
```

## 품질 게이트

최종 보고서는 준비됐다는 주장이 아니라 게이트예요. 각 가지의 실제 점수나 점수가 없는 이유, 리서치 데이터 라벨, 아직 사람이 해야 하는 행동을 모두 보여야 해요. 결과, 트래픽, 매출, 런칭 상태를 지어내지 마세요.

## 워크플로 조정

이미 승인된 동등 에셋이 있을 때만 가지를 빼요. 그 경로를 남은 가지에 주세요. 단계 순서는 유지해요. 쪼개기와 광고는 실제 캠페인 재료를 쓸 수 있기 전에 시작하지 않아요.
