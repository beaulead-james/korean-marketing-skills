# 워크플로: 캠페인 팬아웃

원본 에셋이 끝난 뒤, 활성 플랫폼 여러 개에 네이티브 초안이 필요할 때 쓰는 온디맨드 워크플로예요. 플랫폼마다 전용 처리와 크리에이티브 브리프를 만들고, 검토 전에 유한한 QA 게이트를 돌려요. 보통 `/content-atomizer` 요청보다 넓어서, 브랜드가 실제로 쓰는 플랫폼만 고르세요. 모든 것은 초안이에요. 이 워크플로는 게시, 예약, 미디어 생성, 파일 업로드를 하지 않아요.

한국 기본 후보는 네이버 블로그, 카페 공지, 인스타그램, 스레드, 유튜브 쇼츠, 카카오 채널이에요. 체험단·협찬은 대가성 표시. 친구톡과 문자는 광고성이면 (광고)로 시작해요.

## 워크플로 지도

| 단계 | 일 | 출력 |
|---|---|---|
| 0 | 공유 원본과 증거 브리프 | 모든 작업 흐름이 쓰는 브리프 하나 |
| 1, 병렬 | 플랫폼마다 `/content-atomizer` 하나, 그리고 크리에이티브 브리프 | 네이티브 처리와 브리프 파일 하나 |
| 2 | QA 게이트 | 점수, 겨냥한 재작성 최대 한 번, 그다음 NEEDS HUMAN |
| 3 | 통합 | 팬아웃 보고서와 등록된 캠페인 에셋 |

## 프롬프트

칸을 채운 다음 마케팅 워크스페이스에 붙여 넣어요.

```
완성된 원본 에셋을 팬아웃한다. 경로 또는 URL: <path or URL>. 플랫폼: <실제로 활성인 것만>. 캠페인 슬러그: <campaign-slug>.

너는 오케스트레이터다. 모든 출력은 ./campaigns/<campaign-slug>/social/ 아래이고 사람 검토용 DRAFT다. 게시, 예약, 업로드, 미디어 생성, 외부 플랫폼 변경은 하지 않는다.

0단계. 공유 브리프를 만든다. 원본 전체를 읽고, voice-profile.md, 있으면 positioning.md, learnings.md의 증거 있는 관련 항목을 읽는다. algo-cache.md 또는 content-atomizer 레퍼런스의 현재 플랫폼 사실을 확인하고 낡은 출처를 적는다. 핵심 아이디어, 뒷받침된 주장, 구체적 증거, 쓸 수 있는 훅, 모든 작업 흐름이 유지할 데이터 라벨을 뽑는다. 아직 공개되지 않은 로컬 의도를 공개된 사실처럼 만들지 않는다.

1단계. 병렬로 실행한다. 이름한 플랫폼마다 /content-atomizer 작업 흐름 하나를 보낸다. 각각은 공유 브리프, 브랜드 보이스 적응, 현재 플랫폼 사실을 받고 ./campaigns/<campaign-slug>/social/<platform>/<YYYY-MM-DD>-fanout.md에 네이티브 처리를 쓴다. 크리에이티브 브리프 작업 흐름 하나를 병렬로 보낸다. 처리 중 시각이 필요한 것의 제작 브리프를 ./campaigns/<campaign-slug>/social/creative-briefs.md에 쓴다. 실패한 플랫폼은 문서화된 갭이지, 다른 작업 흐름을 멈출 이유가 아니다.

2단계. QA 게이트. 모든 처리를 0에서 100으로 채점한다. 네이티브 형식 적합성, 훅, 보이스 충실도, 보존된 내용, 슬롭 회피. 기준은 70. 기준 아래 파일은 약한 차원을 적어 자신의 작업 흐름에 한 번만 되돌리고 다시 채점한다. 여전히 70 아래면 점수 이력과 함께 NEEDS HUMAN으로 표시한다. 한 번을 넘겨 재시도하지 말고, 평범한 카피로 조용히 바꾸지 않는다.

3단계. 통합한다. ./campaigns/<campaign-slug>/social/fanout-report.md에 플랫폼·형식·점수 매트릭스, NEEDS HUMAN 항목과 이유, 크리에이티브 브리프 색인, 사람이 발행하는 순서, 적용한 프라이어를 쓴다. Data: LIVE, LOCAL DOCS, MODEL KNOWLEDGE 라벨을 보존한다. 아직 등록되지 않은 파일마다 assets.md 행을 덧붙이고 _system/output-format.md의 요약 형식을 제공한다. 일어나지 않은 발행이나 결과를 주장하지 않는다.
```

## 품질 게이트

점수는 초안이 통할 거라는 증거가 아니라 검토 보조예요. 게이트는 플랫폼 특수성과 사실의 내용을 지키고, 약한 출력을 보이게 해요. 겨냥한 재작성 한 번에서 멈추고, 끝없는 루프가 아니라 사람이 다음을 정해요.

## 워크플로 조정

원본이 복잡하면 플랫폼 3개나 4개로 시작해요. 브리프가 승인되면 별도로 검토할 수 있는 실행에서 `/creative`에 넘기세요. 미디어 생성을 이 워크플로 밖에 두면 사람 승인 지점이 분명해져요.
