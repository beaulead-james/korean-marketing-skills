# 구글 광고 전환 추적

이 스킬은 구글 광고의 통화·폼·예약 추적이에요. 네이버 검색광고나 스마트콜 설치로 바꾸지 않아요. 구글 광고 계정이 있는 사업자만 써요. 네이버 전환은 광고주센터의 전환 추적이고, 여기서 다루지 않아요.

구글 광고는 보이는 것으로만 입찰해요. 지역 서비스 계정은 광고 안의 통화 버튼, 어쩌다 올라온 오프라인 전환, 구글이 세는 비즈니스 프로필 액션만 보이고, 광고를 누르고 페이지를 읽고 전화한 사람은 안 보이는 경우가 많아요. 이 스킬은 무엇이 집계되는지 찾고, 무엇으로 입찰할지 정하고, 태그를 고치고, 기록된 전환으로 고침을 증명해요. 끝났다는 것은 리드 경로가 한 번씩 집계되고, 입찰에 쓰는 액션이 배울 만큼 자주 찍히는 실제 리드이고, 예산 판단이 노출 점유율에 서 있다는 뜻이에요. 방법은 바닥이에요. 눈앞 계정이 더 나은 길을 가리키면 그 길을 가고 이유를 한 줄로 적어요.

하드 룰 둘.

1. **그 변경에 대한 예스 없이 계정을 바꾸지 않아요.** 객체, 필드, 이전, 이후를 보여요. 추천에서 "모두 적용"을 누르지 않아요.
2. **고침은 저장된 설정이 아니라 데이터로 증명해요.** 새 액션이 광고 트래픽에서 실제 전환을 기록하면 끝이에요. 보통 7일 안. 태그 확인이 녹색인 것은 태그가 로드된다는 뜻이지, 구글이 리드를 센다는 뜻이 아니에요.

## 맥락

`./brand/`, `./brands/` 또는 `MARKETING.md`가 있을 때만 실행해요.
`python3 ${CLAUDE_SKILL_DIR}/../start-here/scripts/brand_context.py --for google-ads-tracking`
(`${CLAUDE_SKILL_DIR}`는 이 스킬 폴더예요. Claude Code 밖에서는 이 파일을 읽은 폴더, 예를 들어 `.agents/skills/google-ads-tracking`. 스크립트나 python3이 없으면 브랜드 폴더를 직접 읽어요. `./brands/active`가 가리키면 `./brands/<slug>/`, 아니면 `./brand/`. 이어서 `MARKETING.md`, `preferences.md`, `reads:`의 파일. 없으면 단독으로 진행하고 이것만 물어요. 사이트 URL, 리드가 오는 방법(전화, 폼, 예약), 사이트의 번호가 실제 번호인지 추적 번호인지, 구글 광고 보기 권한.)

**먼저 `references/google-ads-facts.md`를 읽고** 헤더를 봐요. UI 이름, 통화 추적 선택, API 열거형은 바뀌어요. 오늘이 last-verified 더하기 ttl-days를 넘으면 헤더대로 갱신해요. 갱신이 안 되면 출처와 가정에 UI 이름이 last-verified 기준이라고 적어요.

아래 예시는 **한빛설비(대구, 설비)** 예요. 지어낸 상호예요. 한 달에 리드 약 40건, 대부분 전화, 견적 폼은 잘 안 써요. 40은 예시 규모예요.

한국어 UI는 목표, 전환, 요약으로 같은 화면에 가요. 아래 경로의 영문 이름은 도움말과 맞추려고 남겨요. 화면 글자가 다르면 화면을 따라요.

| `fix` | 4단계. 앞서 한 감사의 계획을 써요. 감사가 없으면 1~3을 먼저. 7일 증명이 있으면 끝. |
| `budget` | 5단계. 추적이 이미 증명된 계정. 4단계가 증명 전이면 그 말을 하고 거기서 시작해요. |

## 1단계. 리드 경로 (10분)

광고를 본 뒤 리드가 되는 모든 길과, 구글 광고가 무엇을 세야 하는지 적어요. 계정을 열기 전에 채워요.

| 경로 | 고객이 하는 일 | 세는 것 |
|---|---|---|
| 광고에서 전화 | 광고나 위치 애셋의 통화 버튼 | "Calls from ads" (광고에서 발생한 통화) |
| 클릭 후 번호 탭 | 광고를 누르고, 휴대폰에서 페이지의 번호를 탭 | 웹사이트 통화. "Someone makes a call by clicking a number on my website" |
| 클릭 후 직접 통화 | 데스크톱에서 번호를 읽고 나중에 직접 걸어요 | 착신 번호("Someone calls a number shown on my website") 또는 통화 추적 도구의 번호를 구글 광고로 전송 |
| 클릭 후 폼 | 견적 폼 제출 | 제출 성공이 확인된 뒤에 찍는 웹사이트 액션 |
| 클릭 후 예약 | 온라인 예약 완료 | 예약 확정 이벤트의 웹사이트 액션 |
| 광고를 보고 나중에 비즈니스 프로필에서 전화 | 프로필을 찾아 전화 | 프로필이 연결되고 통화 기록이 켜져 있으면 "Calls from ads". 위치 애셋이 있으면 지역 액션("Clicks to call", "Get directions") |
| 유료 작업이 됨 | 예약하고 결제 | 작업·청구 시스템에서 며칠 뒤 오프라인 업로드 |

그다음 사장님에게 숫자 하나를 물어요. **지난달 전화와 폼 리드가 몇 건이었는지. 전화 기록과 받은편지함 기준이고, 구글 숫자가 아니에요.** 네이버 스마트콜과 카카오 문의는 구글 전환의 분모가 아니에요. 구글이 주장하는 리드가 현장 전화와 맞는지 보는 자예요. 이 숫자가 없으면 구글 전환이 너무 적은지 많은지 판단할 수 없어요.

## 2단계. 구글이 보는 것 (무료, 구글 광고 화면)

1. **Goals, Conversions, Summary** (한국어 화면은 목표, 전환, 요약). 전환 액션마다 `./campaigns/<business-slug>/notes.md`에 적어요. 작업 데이터라 채팅에 붙이지 않아요. 이름, 소스(웹사이트, 광고 통화, 구글 호스팅, 가져오기), 카테고리, 주요 또는 보조, 추적 상태 열, 최근 30일과 90일의 전환과 모든 전환, 집계 설정, 클릭 기여 기간.
2. **어떤 목표가 입찰하는지.** 계정 기본 목표를 적고, 캠페인 설정에서 계정 기본을 쓰는지 캠페인 고유 목표를 쓰는지 봐요.
3. **캠페인 표.** 열을 추가해요. 입찰 전략 유형, 전환, 모든 전환, 검색 노출 점유율, 검색 손실 노출 점유율(순위), 검색 손실 노출 점유율(예산).
4. **비교.** 주요 전환 수와 1단계의 사장님 리드 수.

찾은 것을 이 표에 대세요. 망가진 계정은 두세 줄에 모여요.

| 보이는 것 | 뜻 | 고치는 곳 |
|---|---|---|
| 웹사이트 액션이 없거나 90일 0 | 클릭하고 읽고 전화하거나 폼을 낸 사람을 구글이 못 봐요. 모바일에서는 리드의 대부분인 경우가 많아요 | 4단계 |
| 주요 액션이 분기에 몇 번만 찍힘 | 입찰이 거의 없는 신호로 배워요 | 3단계 |
| 사이트 빌더나 이전 대행사가 남긴, 한 번도 안 찍힌 숨은 웹 액션 | 지저분함. 해는 적어요 | 숨긴 채로 둬요. 삭제는 되돌릴 수 없고 이득이 없어요 |
| 같은 이벤트가 두 번 (광고 태그와 같은 이벤트의 GA4 가져오기, 둘 다 주요) | 부풀린 전환이 입찰에 틀린 교훈을 가르쳐요 | 하나만 주요 |
| 지역 액션이나 비즈니스 프로필 통화가 주요이고 전환의 대부분 | 어차피 올 전화가 포함돼요 | 3단계, 이어서 `/ads-incrementality-check` |
| 입찰 전략이 클릭수 최대화 | 캠페인이 클릭을 사고, 전환이 조향하지 않아요 | 5단계 |
| "Calls from ads"가 5초 통화를 셈 | 스팸과 잘못 걸린 전화가 리드예요 | 최소 통화 시간 (4단계) |

**이 스킬이 나온 자리의 형태.** 웹사이트 전환 신호가 0이고, 입찰 목표는 광고 통화뿐이며, 유료 작업 오프라인 액션은 석 달에 거의 0. 검색 캠페인 둘이 전환 없이 클릭에 예산을 씀. 사이트는 이미 GA4로 번호 탭과 폼 성공을 보내고 있었는데 구글 광고에 연결되지 않음. 새로 만들기 전에 사이트가 이미 보내는 이벤트를 봐요. 특정 업체 실측이 아니라 인수 계정에서 반복되는 패턴이에요.

## 3단계. 무엇으로 입찰할지

계정을 만지기 전에 표로 계획을 써요. 액션, 경로, 소스, 카테고리, 주요 또는 보조, 집계, 클릭 기여 기간, 값. 기본값.

- **주요는 배울 만큼 자주 찍히는 실제 리드예요.** 캠페인당 한 달 주요 전환 약 30건을 목표로 봐요. 구글 최소선이 아니라 작업 규칙이고, 스마트 비딩은 캠페인 단위로 배워요.
- **물량 있는 가장 좋은 신호가 이겨요.** 유료 작업은 가장 좋은 신호이고, 작은 사업에서는 너무 드물고 늦어요. 한 달 리드 15~60건이면 자격 있는 통화, 번호 탭, 진짜 폼으로 입찰해요. 광고 통화와 웹 번호 탭은 다른 길이라 둘 다 주요여도 이중 집계가 아니에요.
- **드문 이벤트는 보조예요.** 한 달에 한 번 쓰이는 폼은 "모든 전환"에만 둬요. 그것만으로 입찰하면 시스템이 유령을 쫓아요.
- **오프라인 유료 작업은 시간이 아니라 데이터로 승격해요.** 직전 90일에 약 60건이 기록되기 전에는 업로드를 보조로 두고, 그 뒤에 값을 달아 주요로 올리고 전환 가치 최대화를 검토해요.
- **리드 액션이 섞인 동안 값을 달지 않아요.** 한 액션만 예시로 150만 원이고 나머지는 없으면, 입찰은 유료 작업과 잘못 누른 탭을 같은 단위로 봐요.
- **리드는 클릭당 하나.** 번호를 두 번 탭해도 리드 하나예요.
- **클릭 기여 기간은 사는 속도.** 긴급 설비는 30일. 지붕, 리모델링, 임플란트처럼 고민하는 일은 60~90일.
- **지역 액션은 보조로 시작해요.** 서비스 지역 업종은 중지 시험이 "없어도 올 전화"가 아니라고 보여 주기 전에는 보조예요. 구글은 클릭 기간 안에 광고 상호작용 뒤의 길찾기·통화 클릭을 세고, 나중 탭이 오가닉 결과에서 왔어도 세요.

**입찰 함정.** 목표가 입찰하는지는 목표(카테고리와 소스)의 계정 설정이고, 액션의 주요 플래그와 별개예요. 목표 안의 유일한 액션을 보조로 내려도 그 목표는 입찰 가능으로 남을 수 있고, 보조로 만든 새 액션이 그 목표를 입찰 가능하게 만들 수 있어요. 변경 뒤에 어떤 목표가 입찰하는지 다시 읽어요. 따라갔다고 가정하지 않아요.

한빛설비 예시. 주요는 60초 이상의 광고 통화와 웹 번호 탭. 보조는 견적 폼, 지역 액션, 오프라인 유료 작업.

## 4단계. 고치기 (무료 경로. 구글 광고 화면과 Tag Assistant)

정확한 라벨은 `references/google-ads-facts.md`예요. 순서.

1. **계정 설정에서 통화 보고를 켜요.** 광고 통화와 착신 번호에 필요해요. 비즈니스 프로필 통화를 세려면 프로필을 구글 광고에 연결하고 프로필에서 통화 기록을 켜요.
2. **광고 통화.** 목표, 전환, 요약, 전환 액션 만들기, 전화 통화 전환, 카테고리 전화 리드, 광고에서 발생한 통화. 최소 통화 시간은 실제 문의가 걸리는 시간(흔히 30~60초). 통화 녹음이 되는 곳에서는 구글의 AI 자격 통화 리드를 쓸 수 있어요. 녹음 가능 국가는 facts 파일을 봐요. 한국 통화를 미국·캐나다 녹음 기능처럼 말하지 않아요.
3. **웹사이트 통화.** 같은 경로, 웹사이트 방문 통화. "사이트 번호를 클릭해 전화"는 전화 링크 탭을 세요. "사이트에 표시된 번호로 전화"는 구글 착신 번호로 바꿔 데스크톱 다이얼도 세요. 통화 추적 도구는 자기 번호로 같은 일을 하고 전환을 구글 광고로 보내요. 웹 통화의 소스는 하나예요. 주요 소스 둘은 같은 전화를 두 번 세요.
4. **폼과 예약.** 전환 액션 만들기, 웹사이트. 확인된 성공에 찍어요. 감사 페이지, 또는 서버가 폼을 받은 뒤 사이트가 보내는 이벤트. 버튼 클릭에는 찍지 않아요. 예약은 예약 확정 콜백이지, 달력이 보인 순간이 아니에요.
5. **설치.** GA4용 구글 태그가 이미 있으면 광고 목적지를 그 태그에 넣어요 (`gtag('config', 'AW-...')`). 두 번째 라이브러리를 또 로드하지 않아요. 태그 관리자면 구글 광고 전환 태그와 전환 링커를 넣고, 전화 링크 탭과 폼 성공에 이벤트 스니펫을 찍어요. 탭 핸들러는 전화 앱을 지연하면 안 돼요. 보내고 잊어요. 네트워크를 기다리지 않아요. 실제 전환 ID와 라벨은 공개 파일에 적지 않아요. 자리표시는 `AW-123456789`처럼 가짜로만.
6. **3단계 계획대로 주요와 보조.** 계정 기본 목표, 캠페인별 목표, 어떤 목표가 입찰하는지 다시 봐요.
7. **Tag Assistant** (tagassistant.google.com). 미리보기가 아니라 라이브 사이트에 연결하고, 휴대폰 너비에서 번호를 탭하고, 시험 폼을 내고, 맞는 AW ID와 라벨로 전환 이벤트가 가는지 확인해요. GA4 이벤트도 아직 찍히는지 봐요. 시험 리드는 CRM에서 지워요. 추적 상태 열은 24~48시간 뒤에 바뀌어요.
8. **증명.** 새 주요 액션이 실제 광고 트래픽에서 0이 아닌 수를 기록해요. 보통 7일 안. 안 되면 고침이 안 끝난 거예요. 7번으로 돌아가요.

일이 적은 업그레이드 둘. 폼의 리드용 향상된 전환(해시된 이메일과 전화. 전환 설정에서 켜고, 화면에서 약관 동의가 필요할 수 있어요). 비즈니스 프로필 웹사이트 링크의 UTM (`?utm_source=google&utm_medium=organic&utm_campaign=gbp_listing`)으로 프로필 방문이 직접 유입에 떨어지지 않게. GA4에서는 번호 탭과 폼 성공을 주요 이벤트로 표시하되, 광고 태그가 이미 세는 동안 그 이벤트를 구글 광고에 주요로 또 가져오지 않아요. 수집한 이메일·전화는 개인정보보호법상 전환 매칭 목적의 고지와 처리 근거가 필요해요. 조문 번호는 단정하지 않아요.

목표를 바꾸면 입찰 학습이 다시 시작돼요. 리드당 비용이 일주일이나 이주일 흔들려요. 이전에는 신호가 없었으면 잃을 것이 없어요.

## 5단계. 입찰 전략과 예산 (4단계가 증명된 뒤)

**입찰 전략을 이름으로 읽어요.** 화면의 입찰 전략 유형 열. API에서는 열거형 이름을 읽고, 손으로 쓴 숫자 지도를 쓰지 않아요. BiddingStrategyType 9는 TARGET_SPEND이고 화면에서는 클릭수 최대화예요. 전환수 최대화는 10이에요. 어떤 감사는 9를 전환수 최대화로 읽고 전략을 두 번 잘못 보고, 맞는 구글 추천을 거절하라고 했어요. 열거형은 매번 공식 참조와 맞춰요. 숫자는 `references/google-ads-facts.md`예요.

**새 주요 액션에 전환이 약 15~30건 기록된 뒤에** 클릭수 최대화에서 전환수 최대화로 바꿔요. 이력이 없는 전환은 없는 것에서 배워요. 전화 업종이 클릭수 최대화에 머물면 안 되는 이유가 둘 더 있어요. 가장 싼 클릭을 사서, 넓은 지도에서는 돈이 좋은 상권이 아니라 싼 동네로 흘러요. 통화가 조향에 전혀 안 들어가요. 전환 입찰로 가면 대부분의 지역 입찰 조정은 무시돼요. 예산이 달라야 하는 상권은 캠페인을 나눠야 하고, 그러면 학습이 갈라져요 (`/paid-ads`의 소액 교훈).

**예산을 올리기 전에 노출을 왜 놓치는지 읽어요.**

- **검색 손실 노출 점유율(예산)** 이 의미 있고(예시로 15% 이상) 한계의 리드당 비용이 받아들일 만하면, 예산이 리드를 더 사요.
- **검색 손실 노출 점유율(순위)** 이 손실의 대부분이면 예산은 거의 아무것도 안 사요. 광고 순위를 먼저 고쳐요. 입찰 전략과 목표, 광고·키워드 연관, 랜딩, 애셋, 그다음 노출이 약 3주 쌓인 뒤의 품질평가점수.

한 계정에서 새 검색 캠페인 둘은 예산 손실이 거의 없고 놓친 노출의 대부분이 순위였어요. 예산을 올려도 달라질 것이 없었어요. 한 달 뒤 넓은 캠페인 하나는 놓친 노출의 대부분이 예산이었어요. 그때의 제약은 돈이었어요. 특정 실측이 아니라 읽는 순서의 예시예요.

**추천은 한 번에 하나.** 자동 적용을 꺼요. 이 계정 데이터로 판단해요. "전환수 최대화로 더 효율적으로 입찰"은 전환이 기록된 뒤면 맞아요. 검색 파트너는 순위 제약이 있는 동안 거절. 비즈니스 로고 추가는 무료. 고객 일치를 기존 고객 제외에 쓰면 어차피 전화할 사람에게 돈을 덜 써요. 고객 일치에 넣는 전화번호·이메일은 개인정보 처리 근거가 필요해요.

## 온라인으로 팔면

방법은 같고 경로가 바뀌어요. 통화 대신 구매, 체험, 가입, 데모 예약, 장바구니를 매핑해요. 구매는 실제 값을 달고, 캠페인당 한 달 약 30건이 기록되면 입찰해요(그다음 전환 가치 최대화 또는 ROAS 목표). 장바구니와 페이지 깊이는 보조. 전화 주문도 받는 상점은 통화 경로를 유지해요. 리드가 몇 주 뒤에 닫히는 소프트웨어·고액은 성사 건의 오프라인 업로드가 유료 작업 역할을 하고, 같은 물량 규칙으로 승격해요. 이중 집계 함정은 같아요. 광고 구매 태그와 가져온 GA4 구매가 둘 다 주요. 예산을 올리기 전의 노출 점유율 읽기도 같아요. 통화 화폐가 원이면 값도 원이에요.

## API 경로 (선택)

구글 광고 개발자 토큰이 있으면 같은 사실을 몇 분에 읽고 고침을 스크립트로 할 수 있어요. 구글 광고 API는 개발자 토큰과 OAuth가 있으면 추가 요금 없이 쓸 수 있어요. 없으면 위의 화면과 Tag Assistant가 같은 일을 해요.
**`references/api-path.md`를 읽어요.** 읽기 쿼리, 고객 전환 목표 수정(리소스 이름은 열거형 이름. `customers/{id}/customerConversionGoals/PURCHASE~CALL_FROM_ADS`. 숫자 형태는 요청 오류), 드라이런 규칙. 읽기는 자유롭게. 쓰기는 모두 하드 룰 1.

## 산출

약 1,200~2,500단어 분량. `./campaigns/<business-slug>/google-ads-tracking.md`를 사장님이나 클라이언트가 읽게 써요.

1. `## GOOGLE ADS TRACKING AUDIT: <business>`와 한 줄. 날짜와 이 감사가 무엇을 위한 것인지.
2. **발견.** 두세 문장. 구글이 세는 것과 지난달 사업자가 받은 리드.
3. **고침 목록.** 단계, 하는 곳, 누가, 상태(완료, 확인됨).
4. **리드 경로와 전환 액션, 지금과 목표.** 표 하나, 경로마다 한 행. 지금 세는 것, 목표(주요 또는 보조, 집계, 기간, 30일·90일 수, 변경). 숨은 액션과 중복은 문제가 될 때만 행.
5. **증명.** 통과한 확인과 날짜. 7일 0이 아닌 확인이 마지막.
6. **입찰과 예산.** 현재 전략, 전환 기준과 다시 볼 날짜, 노출 점유율 읽기, 추천 판정.
7. **출처와 가정.** 짧은 노트. 무엇을 언제 읽었는지 평범한 말(계정 화면, API, 스크린샷), 판단의 기준이 된 사장님 리드 수, 빠진 것. 사이트 URL, 계정 접근, 리드 수가 없으면 그 한 줄. 플레이스홀더 도메인에 Tag Assistant나 추적 확인을 돌리지 않아요.

원본 읽기(액션 전체, 캠페인 열, 쿼리 출력)는 `notes.md`에만. 보고서에 스크립트 경로와 명령은 없어요.

`./brand/assets.md`에 한 줄. 파일이 먼저, 채팅 요약은 `start-here/references/output-format.md`를 따라요.
