# 리드 응답 속도

지역 사업자의 첫 문제는 리드 부족이 아닌 경우가 많아요. 모두 현장에 있는 동안 전화가 울리고, 음성사서함은 저녁에야 보고, 견적은 나가고 아무도 안 쫓아요. 그 고객은 목록의 다음 업체로 가요. 이 스킬은 사업자 자신의 통화 기록으로 새는 곳을 재고, 가장 큰 곳을 이름 붙이고, 콜백마다 담당과 시간 한도를 붙여 고침을 준비해요. 끝났다는 것은 실제 데이터의 점수표, 사장님이 승인한 뒤 시험까지 끝난 부재중 알림톡·문자, 글로 된 "누가 언제까지 다시 거는지", 견적 후속 주기, 다시 잴 날짜예요. 방법은 바닥이에요. 눈앞 사업자에 다른 고침이 필요하면 그 고침을 하고 이유를 말해요.

기본 회신은 부재중 알림톡과 문자예요. 미국 10DLC 등록은 기본 절차가 아니에요. 미국 현지 번호로 문자를 보낼 때만 해당하고, 한국 고객이 기본이면 쓰지 않아요.

하드 룰 둘.

1. **통화 기록과 발신 번호는 워크스페이스에만 둬요.** 아무도 못 닿은 발신 목록은 콜백하는 사람에게만 가고, 공유 보고서, 공개 파일, 커밋에는 들어가지 않아요.
2. **사장님이 정확한 문장을 승인하기 전에는 고객에게 자동 문자를 보내지 않아요.** 알림톡은 검수된 템플릿이 있어야 하고, 문자가 홍보면 아래 광고성 정보 규칙을 갖춰요. 방금 한 전화에 대한 안내이지, 승인도 없이 쿠폰을 넣지 않아요.

**광고성 정보.** 문자가 할인, 이벤트, 재방문 권유, 후기 부탁처럼 홍보면 정보통신망법의 광고성 정보로 봐요. 시작에 `(광고)`, 보내는 이 명칭과 연락처, 수신거부 방법. 야간 21시~08시는 별도 동의가 있어야 보내요. 방금 놓친 전화에 "곧 다시 걸겠습니다"만 있으면 정보성으로 볼 수 있고, 그 자리는 검수된 알림톡이 맞아요. 혜택이 한 줄이라도 섞이면 광고성으로 봐요. 조문 번호는 단정하지 않아요. 법률 자문이 아니에요. 수집한 번호와 이메일은 개인정보보호법상 목적 고지와 처리 근거가 필요해요.

## 맥락

`./brand/`, `./brands/` 또는 `MARKETING.md`가 있을 때만 실행해요.
`python3 ${CLAUDE_SKILL_DIR}/../start-here/scripts/brand_context.py --for speed-to-lead`
(`${CLAUDE_SKILL_DIR}`는 이 스킬 폴더예요. Claude Code 밖에서는 이 파일을 읽은 폴더, 예를 들어 `.agents/skills/speed-to-lead`. 스크립트나 python3이 없으면 브랜드 폴더를 직접 읽어요. `./brands/active`가 가리키면 `./brands/<slug>/`, 아니면 `./brand/`. 이어서 `MARKETING.md`, `preferences.md`, `reads:`의 파일. 없으면 단독으로 진행하고 이것만 물어요. 통화 기록 내보내기, 영업시간, 언제 누가 전화를 받는지, 오늘 부재중이면 무슨 일이 일어나는지.)

보이스 프로필이 회신 문장을 다듬어요. 고객 아픔 말이 있으면 첫 문자가 약속하는 것을 다듬어요. 보고서는 어떤 파일을 읽었는지 말하지 않아요.

아래 예시는 **한빛설비(대구, 설비)** 예요. 지어낸 상호. 평일 9시에서 6시까지 사무실이 받고, 대표는 현장에 있고, 주말은 아무도 안 받고, 긴급 출장이 매출의 한 몫이에요. 비율은 예시예요.

## 1단계. 데이터 (15분)

- **통화 기록 내보내기.** 30~90일, 모든 회선, 양방향. 통신사 인터넷전화(KT, LG U+, SK브로드밴드), 대표번호, 상담콜, 채널톡이 남기는 CSV. 네이버 스마트콜 연결 이력은 있으면 같이. 해외 도구(Quo, CallRail, RingCentral, Google Voice)는 그 도구를 실제로 쓸 때만.
- **문자·알림톡·카카오 로그.** 같은 번호나 채널에서 보냈으면, 회신이 후속으로 집계되게.
- **폼과 메시지 리드의 시각.** 웹 폼 알림 메일, CRM, 메타 리드 양식, 네이버 톡톡, 카카오 채널 1:1, 당근 채팅. 도착 시각과 사람이 처음 답한 시각. 미국 리뷰 사이트를 기본 목록에 넣지 않아요.
- **열린 견적.** 보낸 날, 금액(원), 상태, 마지막 연락. 견적 도구나 스프레드시트.

빠진 것은 보고서에 한 줄("통화 기록이 없어 점수표 없음"). 숫자를 지어내지 않아요. 통화 기록이 없으면, 있는 영업시간과 대답으로 문장, 콜백 담당, 견적 주기만 내요.

## 2단계. 측정 (점수표)

내보내기에 스크립트를 돌려요. 열을 추측해 인쇄해요.

```
python3 ${CLAUDE_SKILL_DIR}/scripts/call_log.py summary calls.csv --texts messages.csv \
  --hours "Mon-Fri 09:00-18:00" --utc-offset 9 --exclude staff-numbers.txt \
  --out never-reached.csv
```

요일은 영어 약어 `Mon-Fri`예요. 스크립트가 그 철자만 알아요. 한국 CSV를 넣기 전에. 방향 "수신/발신"은 `inbound` / `outbound`로 바꾸세요. 상태 "부재중", "음성사서함"은 영어 단어(missed, voicemail)가 아니면 통화 시간으로만 나뉘어요. 시각은 `YYYY-MM-DD HH:MM:SS`. 타임존이 붙은 UTC만 `--utc-offset 9`가 한국 시간으로 옮겨요. 이미 한국 시각이고 타임존이 없으면 오프셋은 적용되지 않아요. 번호는 끝 10자리 키라 `010`과 `82 10`은 맞고, 서울 `02`는 다섯 줄을 눈으로 봐요. 세부는 `references/call-log-recipe.md`.

점수표와 각 숫자가 말하는 것.

| 지표 | 보여주는 것 |
|---|---|
| 하루 수신, 고유 발신 | 기회의 크기 |
| 영업시간 안·밖 수신율 | 어디서 전화를 놓치는지 |
| 음성사서함 없는 부재중과 음성사서함 | 메시지를 남긴 사람이 가장 따뜻함. 대부분은 그냥 끊어요 |
| 요일·시간대별 부재중 | 커버를 더할 때(점심, 아침 몰림, 퇴근 직전) |
| 부재중 후속, 대기 중앙값, 5분·1시간 안 비율 | 콜백 담당이 있는지 |
| 못 닿은 발신 | 잃은 리드. 번호는 콜백하는 사람의 CSV에만 (CRM에서 이름을 붙임) |
| 반복 발신 | 이미 잡힌 일을 쫓는 고객. 회선을 붙잡음 |
| 폼·카카오·톡톡의 첫 답 시간 (손. 중앙값과 최악) | 느린 채널의 같은 샘 |
| 연락 없이 7일이 지난 견적 | 값은 매겼는데 아무도 안 쫓는 일 |

전화 시스템마다 "받았다"의 뜻이 달라요. 벤치마크와는 방향만 비교하고 소수점은 비교하지 않아요. `references/speed-evidence.md`에 날짜 있는 자료와 출처가 있어요. 영어권 업체 통계는 한국 수신율로 인용하지 않아요.

**이 스킬이 나온 자리의 형태.** 한 달 통화 기록에서 수신 고객 전화의 상당수가 부재중이고, 일부는 전화도 문자도 다시 가지 않았어요. 고객 전화의 많은 부분은 이미 진행 중인 일(도착, 청구, 부품)이었어요. 그 상태 전화가 회선을 잡는 동안 신규가 못 들어왔어요. 특정 업체 실측이 아니라 패턴이에요.

## 3단계. 새는 곳의 이름

점수표가 보여 주는 것을 주당 잃은 리드로 줄 세우고, 가장 큰 것부터.

- **매주 같은 시간에 영업시간 중 부재중.** 라우팅. 링그룹, 휴대폰 착신, 피크 시간의 응대 인력.
- **영업시간 밖 수신율이 낮음.** 업종에 따라 고침이 달라요 (4b).
- **부재중 후속이 느리거나 없음.** 콜백 담당이 없음. 가장 흔하고 가장 싸게 고쳐요.
- **음성사서함을 몇 시간 뒤에 돌려줌.** 가장 따뜻한 발신이 가장 오래 기다려요.
- **잡힌 일을 묻는 반복 발신.** 상태 문자가 회선을 비워요.
- **폼·카카오를 분이 아니라 시간에 답함.** 알림이 아무도 안 보는 메일함으로 가요. 전화로 보내요.
- **견적을 안 쫓음.** 주기도 담당도 없음.

## 4단계. 고침

**4a. 부재중 회신.** 무료부터. 많은 인터넷전화와 상담 도구에 부재중 자동 안내가 있어요. 설정에서 "부재중", "자동 응답"을 찾아요. 없으면, 부재중이 들어올 때 같은 대표번호로 문자를 보내는 연결을 만들 수 있어요. 답장이 그 번호로 돌아와야 해요.

우선순위.

1. **알림톡.** 정보성. 카카오 채널과 검수된 템플릿이 있을 때. "방금 전화를 놓쳤고, 몇 분 안에 다시 겁니다"처럼 홍보가 없는 문장. 템플릿 검수 전에는 못 보내요.
2. **문자 SMS/LMS.** 알림톡이 없거나 검수 전. 같은 정보성 문장. 대표번호로.
3. **친구톡.** 채널 친구에게 보내는 광고성. 부재중 첫 답이 아니에요. 할인·이벤트는 여기나 광고 문자로, `(광고)`와 수신거부를 갖춰요.

문장 규칙. 사업자 번호에서 오고, 상호와 사람 이름이 있고, 사람이 언제 다시 거는지 말하고, 답장을 권하고, 안 팔아요. 템플릿은 `references/text-back-and-follow-up.md`.

미국 번호로 문자를 보낼 때만, 통신사 경유 10DLC 등록이 전달 조건이에요. 한국 고객이 기본이면 그 절차를 시작하지 않아요. 등록과 동의는 다른 문제예요. 방금 한 문의에 답하는 것과, 홍보 목록에 넣는 것은 달라요. 홍보 전에 동의를 받아요.

**4b. 영업시간 밖. 일의 종류.**

| 상황 | 기본 |
|---|---|
| 긴급 (설비, 계절의 냉난방, 견인, 열쇠, 누수) | 사람이 받음. 당직 착신, 응대 인력, 또는 안내 전화. 알림톡·문자는 뒷받침 |
| 예약제 (청소, 학원, 병원, 미용) | 예약 링크가 있는 회신과 "8시에 전화드립니다". 새 전화보다 아침 콜백이 먼저 |
| 아무도 안 받을 것이고 사업자가 그걸 받아들임 | 누군가 받는 시간에만 전화 목적 광고 (`/paid-ads`). 아무도 안 받는 전화에 돈을 쓰는 것이 가장 비싼 리드예요 |

응대 대행과 자동 응대는 매달 돈이 들어요. 긴급 일 한 건의 가치와 견주어 보고, 연 계약 전에 한 달을 시험해요.

**4c. 누가, 언제까지.** 시간 블록마다 이름 한 명. 글로. 기본.

- 영업시간 중 부재중. 5분 안에 다시 걸기.
- 음성사서함. 15분 안.
- 영업시간 밖. 오픈 후 30분 안, 새 일보다 먼저.
- 웹 폼, 카카오, 톡톡. 즉시 정보성 접수 안내, 영업시간에는 사람 답변 5분 안.
- 못 닿은 목록. 10시, 1시, 4시에 보고, 마감 전에 비움.

속도는 웹 리드 연구보다 지역 긴급에서 더 중요해요. 바닥에 물이 찬 사람은 목록의 다음 번호로 걸어요. 부재중을 알아차리기 전에 자주 그래요.

**4d. 견적 후속.** 보낸 견적의 기본 주기. 견적마다 담당 하나. 예스나 노가 오면 멈춰요. 이 스킬은 담당과 시각을 정해요. 모든 접점을 글로 쓰려면 `/email-sequences`. 홍보가 섞인 날(3일, 14일의 권유)은 광고성 정보 규칙을 갖춰요. 0일의 "견적 보냈습니다"는 요청한 견적에 대한 정보성으로 알림톡이 맞아요.

| 날 | 접점 |
|---|---|
| 0 | 견적을 보내고 문자 또는 알림톡. 보냈고, 질문 있으면 답장 |
| 1 | 전화. 같이 보자고 |
| 3 | 쓸모 있는 것. 비슷한 현장 사진, 이웃 후기. 할인이 들어가면 `(광고)` |
| 7 | 전화 |
| 14 | 마감할지 묻는 문자 (답장이 와요). 권유면 광고성 규칙 |
| 30~60 | 계절 안부는 `/email-sequences`. 홍보면 수신 동의와 `(광고)` |

CRM, 견적 도구, 또는 "다음 연락" 날짜가 있는 시트. 큰 일(지붕, 설비 교체)은 간격을 늘리고, 작은 일은 줄여요.

**4e. 상태 문자.** 예약 때 하나, 기사가 출발하며 도착 폭 하나, 일이 끝나고 청구 링크 하나. "기사님 어디예요" 전화가 줄면 신규를 받을 회선이 늘어요. 이 셋은 정보성 알림톡 후보예요.

**도구는 모두 선택.** 먼저 전화 시스템 자신의 기능. 현장 관리 소프트웨어의 알림과 견적 후속. 전화와 문자·CRM을 잇는 자동화. API 메모는 `references/call-log-recipe.md`. 해외 전화 API를 기본 경로로 두지 않아요.

## 5단계. 시험하고 다시 재기

라이브라고 부르기 전에. 개인 휴대폰으로 영업시간 안과 밖에 걸고, 벨이 끝날 때까지 두고, 음성사서함을 한 번 남기고, 각 문자가 맞는 말로 도착하는지 봐요. 알림톡이면 검수된 문구 그대로인지. 웹 폼을 내고 접수 안내와 사람 답의 시간을 재요. 21시 이후에 광고성 문자가 나가지 않는지 봐요.

2~4주 뒤 기록을 다시 내보내고 같은 설정으로 스크립트를 돌려요. 수신율, 후속 시간, 못 닿은 발신을 첫 점수표와 비교해요. 표본이 작으면 흔들려요. 하루가 아니라 몇 주의 방향을 봐요.

## 온라인으로 팔면

방법은 같아요. 리드는 데모 요청, 채팅, 문의 폼, 체험 가입이고 사람이 필요해요. 채널과 시간대별 첫 답 시간을 재고, 즉시 접수 안내와 영업시간 중 몇 분 안의 사람 답을 두고, 열린 거래마다 후속 주기와 담당을 줘요. 응답 시간 연구의 대부분은 웹 리드라, 그 방향은 여기에 더 직접 맞아요. 숫자 자체는 `references/speed-evidence.md`가 영어권이라고 밝힌 것만 인용해요.

## 산출

`./campaigns/<business-slug>/speed-to-lead.md`. 사장님과 사무실이 일하는 한 장. 계획 분량 약 1,200~2,500단어, 문장 포함.

1. `## SPEED TO LEAD: <business>`, 이어서 날짜와 통화 기록 구간 한 줄.
2. **새는 곳.** 가장 큰 것, 주당 잃은 리드. 나머지는 한 줄씩. 그 아래 2단계 점수표(데이터 없는 행은 빼고, 각 숫자가 뜻하는 몇 단어).

4. **누가 무엇을.** 이름, 시간 블록, 콜백 한도, 견적 주기와 담당.
5. **설정 체크.** 알림톡 템플릿 검수, 정보성 자동 응답 켜짐, 광고성 문자는 `(광고)`·수신거부·야간 동의, 시험 통화, 견적 주기 가동. 10DLC는 미국 번호를 쓸 때만 칸을 만들어요.
6. **다시 잴 날.** 날짜.
7. **출처와 가정.** 통화 기록이 덮는 것(날짜, 통화 수), 빠진 내보내기, 쓴 벤치마크와 그것이 영어권·업체 자료인지, 사장님이 확인할 것. 평범한 말, 10줄 안. 스크립트가 인쇄한 열 추측과 다른 작업 출력은 `./campaigns/<business-slug>/notes.md`이지 보고서가 아니에요.
