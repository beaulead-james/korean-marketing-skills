# 출력 형식

모든 스킬이 이 계약을 따릅니다. 일부러 짧습니다. 계약은 네 절, 선택용 빠른 선택, 특정 요청용 빠른 모드, 아래 산출물 위생입니다. 나머지는 절제입니다.

## 원칙

1. **마크다운 그대로.** Claude Code가 마크다운을 렌더합니다. 노션, 슬랙으로 보낸 글, 산출물이 닿는 편집기도 그렇습니다. 제목, 굵은 라벨, 표, 목록을 씁니다. 유니코드 상자, 아스키 구분선, 고정 줄 너비는 없습니다. 고정폭 글꼴이어야 예뻐 보이는 출력은 다른 곳에서는 깨집니다.

2. **파일 먼저, 출력 다음.** 산출물은 채팅에 요약하기 전에 디스크에 있습니다(`./brand/`, `./campaigns/<이름>/`). 긴 내용(전문, 전체 시퀀스, 자세한 브리프)은 파일에 있고, 채팅은 저장한 것, 핵심 결정, 다음 길을 보여 줍니다. 산출마다 `./brand/assets.md`에 한 줄. 빠른 모드는 이것을 건너뛰고, 한 번짜리 산출을 위해 `./brand/`를 만들지 않습니다.

3. **5초에 훑임.** 산출물 이름, 권하는 선택, 다음 단계가 스크롤이나 사냥 없이 보입니다. 예측 가능한 절 순서가 이 일의 대부분을 합니다.

4. **절제.** 이모지 없음. 느낌표 없음. "좋은 소식입니다" 같은 채움 없음. 서두 없음("여기 있습니다", "만들었습니다"). 출력은 머리에서 시작합니다. 출력이 산출물입니다. 내놓고 넘어갑니다.

5. **권하는 선택이 바로 보임.** 여러 선택을 낼 때 고른 것이 먼저(빠른 선택), 세부는 다음입니다.

6. **고객은 일을 읽지, 과정을 읽지 않습니다.** 에이전트가 거기 도달하려고 한 일은 산출물 밖에 있습니다. 산출물 위생을 보세요.

## 네 절 계약

모든 스킬 출력이 이 순서로 이 절을 가집니다. 정말로 해당 없으면(드묾) 왜 한 줄로 적고 절은 둡니다. 굵은 라벨은 영어 그대로 둡니다. 다른 스킬이 이 말을 찾습니다.

### 1. 머리

```markdown
## 랜딩 문안. 봄 점검
2026-06-10 · 봄 설비 점검용
```

`##` 제목이 산출물을 이름 붙입니다(출력 유형이지 스킬 이름이 아님). 그다음 한 줄. 날짜와 무엇에 쓰는지. 어떤 브랜드 파일, 각도, 모드, 도구가 실행을 빚었는지는 적지 않습니다.

### 2. 내용

산출물 요약, 또는 짧으면 산출물 자체, 그다음 짧은 "출처와 가정" 하나(산출물 위생). 깨끗한 마크다운.

- 구조는 제목, 라벨은 굵게, 항목은 목록.
- 표는 정말로 나열되는 사실(키워드 지표, 발송 일정, 변형 비교)에만. 한 열짜리 상태 목록에 쓰지 않고, 같은 표를 두 번 쓰지 않습니다.
- 추정 숫자는 `~`. 전체의 데이터 품질은 노트에, 평범한 말로, 한 번. 줄이나 행마다 태그를 달지 않습니다. 그림이면 예시. 통화는 원.

### 3. 저장한 파일

```markdown
**저장한 파일:**
- ./campaigns/spring-check/landing-page.md (new)
- ./brand/positioning.md (updated)
- ./brand/assets.md (1 entry appended)
```

정확한 상대 경로와 `(new)` / `(updated)` / `(n entries appended)`. 파일을 쓰는 모든 스킬이 무엇을 썼는지 보여 줍니다. 사용자가 산출을 사냥하지 않습니다. 아무것도 안 썼으면(분석만) `파일을 쓰지 않았습니다. 분석만 했습니다.`라고 말합니다.

### 4. 다음

```markdown
**다음:**
- /email-sequences: 이 페이지를 환영 5통으로 (약 15분)
- /creative: 크리에이티브 키트에서 첫 화면 이미지 (약 10분)
- /content-atomizer: 우선 채널 2곳에 알림 (약 10분)

지금 하는 일을 말해 주시면 그쪽으로 보내겠습니다.
```

구체적인 `/skill` 2개에서 4개, 각각 이유와 대략의 시간. 라우팅 폴백 줄로 끝냅니다. 워크플로가 여기서 끝나면 그렇다고 말하고, 현황은 `/start-here`를 가리킵니다. 저장한 파일과 다음은 산출물 뒤에 있지, 산출물 안이 아닙니다. 저장된 파일 자체에는 스킬 이름이나 다음 스킬 라우팅이 없습니다.

**조건부 /creative.** 둘 다 참일 때만 시각 제작을 제안합니다. Replicate가 연결되어 있고(`.env`나 stack.md에 키), 산출 유형이 시각을 실제로 필요로 할 때(랜딩 첫 화면, 광고 소재, 소셜 그래픽. 키워드 계획이나 메일 시퀀스는 아님). 제안되면 목록의 선택이지, 자동으로 다음 단계가 아닙니다.

## 산출물 위생

고객 산출물에는 일만 있습니다. 끝난 문안, 페이지, 계획, 다음 단계. 고객이 쓸 순서. 끝난 조각 먼저(페이지, 메시지, 광고), 그다음 돌릴 계획, 그다음 다음 단계. 과정은 밖에 있습니다.

**산출물에 절대 보이지 않는 것.**

- 스크립트 경로(`start-here/scripts/...` 같은 것)나 에이전트가 돌린 명령.
- 일을 만들려고 쓴 도구, 스킬, 커넥터, 능력 단계의 이름("이 경로로", "강화 단계", "Firecrawl을 돌림"). 고객이 사거나 써야 하는 도구를 계획 안의 권고로 말하는 것은 괜찮습니다.
- 자기 점수, 루브릭, 품질 표, 점수 이력, 통과·실패 체크리스트.
- 내부 데이터 라벨 장부. 줄이나 행의 `Data:` 태그, 근거 ID, 출처 품질 코드.
- "매트릭스 상태", 칸 ID와 채움 상태, 원장, 워터마크, 라우팅 영수증, 어느 브랜드 파일을 불러왔다는 줄.

**품질 검사는 조용히.** 채점하고, 약한 곳을 찾고, 다시 쓰고, 다시 채점하는 것은 내부 단계입니다. 통과한 일만 보여 줍니다. 약점을 고칠 수 없으면 노트에 한 줄로 그것이 무엇인지 말합니다.

**출처와 가정.** 근거와 가정은 내용 끝의 짧은 노트 하나, 최대 10줄. 일이 무엇에 기대는지(출처와 날짜를 문장으로), 평범한 말의 데이터 품질, 고객이 확인할 것, 빠진 것. 일을 바꾼 학습은 한 줄, 바꿨을 때만. 저장한 검사를 돌렸으면(`taste-loop.md`) 한 줄이 말할 수 있습니다. "저장한 검사 9개와 맞춰 봤습니다." SEO와 AI 검색 스킬의 빈칸 영수증(무엇을 확인했고, 무엇을 못 했고, 다음을 여는 것)은 그 줄 중 최대 3줄입니다. 더 길면 작업 파일로 갑니다.

**작업 파일.** 근거 묶음, 주장별 출처, 점수 이력, 도구와 라우팅 출력, 매트릭스 장부는 `./campaigns/<이름>/notes.md`나 속하는 브랜드 파일에 있습니다. 저장하지, 붙여 넣지 않습니다. 저장한 파일 목록은 그것들을 최대 한 번 이름 붙입니다.

**빈 입력은 한 줄.** 무엇이 빠졌는지("도메인이 없어서 DNS나 도달 검사를 안 했습니다"). 자리표시(yourdomain.com, [상호], example.com)를 길게 감사하거나 그것에 검사를 돌리지 않습니다.

**한 가지는 한 번.** 중복 표 없음, 본문을 다시 말하는 요약 없음, 채팅이 이미 보여 준 것이나 파일이 이미 가진 것의 재진술 없음.

**일 유형별 길이.**

| 일 | 예산 |
|---|---|
| 페이지나 랜딩 | 문안 약 800단어에서 1,500단어 |
| 계획 | 약 1,200단어에서 2,500단어 |
| 메일이나 문자 시퀀스 | 메시지에 메모 200단어 |
| 광고 묶음 | 광고에 짧은 시험 계획 |

요청이 조각을 더 달라고 명시할 때만 더 길게. 여분을 안 물었는데 예산을 넘으면 자릅니다. 일이 아니라 과정인 것부터.

## 빠른 선택

스킬이 여러 선택(각도, 콘셉트, 제목 변형)을 낼 때, 권하는 것이 자세한 선택보다 위에 있습니다.

```markdown
**빠른 선택: ★ 2번. 질문 후크**
"제안서 양식 때문에, 예를 들어 월 500만 원에서 멈춰 있다면요?"
누구에게. 차가운 유입, 의심하는 구매자. 아래가 모든 선택입니다.
```

별 하나, 사용자가 전체 목록에서 찾을 번호, 한 줄 이유나 문안 발췌. 명확한 승자가 없으면 블록을 건너뜁니다. 권고를 지어내지 않습니다. 500만 원은 형식 예시입니다.

## 빠른 모드

사용자가 특정한 산출물 하나를 말하면("이 주제로 인스타 글", "제목 5개", "상품 사진") 의식을 건너뛰고 넘깁니다.

- 프로젝트 현황 스캔, 여러 단계 제안, 빈칸 분석, 없는 파일 경고는 없습니다.
- 산출물만(파일 먼저 원칙대로 디스크에는 저장), 그다음 다음을 한 줄.

**빠른 모드는 "먼저 스캔" 규칙을 이깁니다.** 스킬 자신의 지시가 만들기 전에 맥락을 감사하고, 계획을 제안하고, 브랜드 기초를 확인하라고 해도, 특정한 산출물 하나짜리는 그것을 덮습니다. 먼저 넘깁니다.

**빠른 모드가 아님.** "도와줘", "어디서 시작하지", "세팅해 줘". 탐색은 전체 경험입니다.

## 상태 표시

내용 절 안에 아껴 쓰는 표시 셋.

| 표시 | 뜻 |
|---|---|
| ✓ | 있음 / 통과 / 저장 |
| ✗ | 없음 / 실패 |
| ★ | 권하는 선택 |

팔레트는 이것뿐입니다. 진행 스피너, 동그라미 숫자, 별점 행, 트리 글리프는 없습니다. 상태 표시가 에이전트가 확인한 것의 상태 표가 되지 않습니다.

## 하지 말 것

- **상자나 구분선 그림 없음.** `━━━`, `───`, 상자, 트리, 원 숫자 없음. 마크다운 제목, 목록, 번호 목록.
- **글자 수 세기 없음.** 고정 줄 너비, 공백으로 맞춘 열, 들여쓰기 도해 없음. 보통 마크다운을 쓰고 렌더러에게 맡깁니다.
- **서두 없음, 맺음 없음.** 머리에서 시작하고 다음에서 끝납니다.
- **이모지 없음.** 출력 어디에도.
- **산출물을 쏟지 않음.** 2,000단어 글을 채팅에 붙여 넣는 것은, 저장했어도 버그입니다.
- **고아 출력 없음.** 저장한 파일이나 다음이 없으면 버그입니다.
- **과정 누출 없음.** 산출물 안의 스크립트 경로, 점수표, 줄마다 다는 데이터 태그, 도구나 단계 이름, 매트릭스 상태는 버그입니다.
- **지어낸 지표 없음.** 숫자가 필요한 예는 예시라고 표시합니다. 추정은 `~`이고, 출처와 가정이 어디서 왔는지 말합니다. 통화는 원입니다.

## 완성된 출력 모양 (예시)

```markdown
## 제목 후보. 환영 1통
2026-06-10 · 환영 흐름용

**빠른 선택: ★ 1번. 증거와 구체**
"이 제안서 양식으로 고객 3곳을 잡았습니다"

1. ★ "이 제안서 양식으로 고객 3곳을 잡았습니다", 증거와 구체
2. "제안서 양식이 고장 났습니다 (제 것을 드립니다)", 호기심
3. "전화를 잡는 3통", 쓸모, 분명한 가치

권하는 비교. 1번 대 2번. 3곳은 형식 예시입니다.

**출처와 가정:**
- 과거 발송과 지금 말투 메모로 썼습니다. 라이브 조사는 없습니다.
- 5월 이 명단에서 질문형 제목이 증거형보다 약해서 1번이 앞입니다. 배율은 그 내보내기에 있을 때만 적습니다.

**저장한 파일:**
- ./campaigns/welcome-flow/subject-lines.md (new)
- ./brand/assets.md (1 entry appended)

**다음:**
- /email-sequences: 이긴 제목 뒤의 본문 (약 10분)

지금 하는 일을 말해 주시면 그쪽으로 보내겠습니다.
```

국내이면 환영의 기본 채널은 카카오 채널이나 문자이고, 이메일은 그다음입니다. 광고성이면 앞에 (광고), 보내는 이 명칭과 연락처, 수신거부가 본문에 있습니다. 이 예시 제목은 정보성 환영으로 둔 형식입니다.
