# 구조화 데이터와 사업 개체

마크업을 권하기 전과, 발견이 구조화 데이터·상호·전화번호에 닿을 때 읽으세요. 여기의 판단은, 마크업은 페이지가 이미 말하는 것을 도울 뿐이고, 어디서나 같은 방식으로 자기를 설명하는 사업을 검색과 AI 답이 알아보기 쉽다는 것입니다.

## 어떤 마크업을 권할 만한가

페이지 본문이 받칠 때만 유형을 권하세요. 페이지가 보여 주지 않는 것을 주장하는 마크업은 없는 것보다 나쁩니다.

| 유형 | 권할 때 | 건너뛸 때 |
|---|---|---|
| Organization, 또는 LocalBusiness와 하위 유형 (Plumber, Dentist, HVACBusiness 등) | 항상, 한 번, 홈에 (지역 사업은 연락 페이지에도) | 건너뛰지 않음. 없을 때 여기저기 넣을 가치가 있는 블록 하나 |
| WebSite | 홈. 사이트 이름을 밝힘 | 그것만으로는 거의 중요하지 않음 |
| BreadcrumbList | 페이지에 실제 빵부스러기가 있음 | 보이는 경로가 없음 |
| Article / BlogPosting | 제목, 날짜, 저자가 있는 편집 글 | 서비스·상품 페이지 |
| Offer가 있는 Product | 보이는 가격으로 상품 하나를 파는 페이지 | 카테고리, 정가 없는 서비스 |
| Service | 서비스, 지역, 제공자를 부르는 서비스 페이지 | 실제 본문의 대체물로 |
| FAQPage | 그 페이지에 질문과 답이 보임 | 손님에게 숨긴 질문, 마크업만을 위해 쓴 질문. FAQ 리치 결과는 사라졌으므로 가치는 깨끗한 질문·답 구조이지 검색 기능이 아님 |
| Event, Recipe, VideoObject, JobPosting | 페이지가 바로 그것일 때 | 그 외 |
| HowTo | 추가하지 않음 | 리치 결과는 2023년에 끝남. 깨지지 않았으면 있는 마크업은 그대로 |
| 자기 사업에 대한 AggregateRating / Review | 추가하지 않음 | 구글은 사업이 자기에 대해 낸 리뷰의 별점을 보여 주지 않고, 바뀌지 않는 고정 평점은 가짜로 보입니다. 네이버 영수증 리뷰를 스키마 별점으로 베끼지 마세요 |

있는 것을 고치는 편이 더 넣는 것보다 낫습니다. 깨진 JSON-LD가 있는 페이지는 그것에서 아무것도 얻지 못합니다. 다른 것보다 문법을 먼저 고치세요 (구글 리치 결과 테스트와 Schema Markup Validator가 실패 줄을 가리킴). 네이버는 같은 리치 결과를 보장하지 않습니다. 마크업은 귀속용으로 말하고, 네이버 상위 노출을 약속하지 마세요.

## 사업 블록

홈 블록은 다른 곳과 같은 방식으로 사업을 한 번 부릅니다. 사장님이 확인했거나, 사이트와 스마트플레이스에 이미 있는 사실만 채우세요. 프로필, 설립일, 주소를 지어내지 마세요.

```json
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "name": "<스마트플레이스와 같은 상호>",
  "url": "https://<domain>/",
  "logo": "https://<domain>/<logo file>",
  "telephone": "<대표번호>",
  "address": {
    "@type": "PostalAddress",
    "streetAddress": "<도로명>",
    "addressLocality": "<구 또는 시>",
    "addressRegion": "<광역시·도>",
    "postalCode": "<우편번호>",
    "addressCountry": "KR"
  },
  "areaServed": ["<구>", "<구>"],
  "sameAs": ["<네이버 플레이스 URL>", "<카카오맵 URL>", "<유튜브나 다른 실제 프로필>"]
}
```

한빛설비 (대구, 설비, 예시)라면 name은 "한빛설비" 하나이고, addressRegion은 대구광역시, areaServed는 실제로 나가는 구만입니다. 출장만 하고 매장에서 손님을 받지 않으면 도로명은 빼고 구를 남기세요. 소프트웨어와 온라인 사업은 Organization을 쓰고 주소를 뺍니다. 구글 비즈니스 프로필 URL은 구글·외국인 손님이 있을 때만 sameAs에 넣으세요.

## 개체 일치

검색과 AI 답은 이름이 나타나는 장소들로 그 이름이 어느 사업인지 정합니다. 감사는 사이트에서 볼 수 있는 불일치를 표시합니다. 수정 목록은 사장님에게 나머지를 확인해 달라고 해야 합니다.

- **상호 하나.** 제목, 사업 마크업, 푸터, 스마트플레이스, 카카오맵, 디렉터리의 철자가 같습니다. 예시로 "한빛설비"와 "한빛설비 종합설비"는 기계에게 두 사업으로 읽힐 수 있습니다.
- **대표번호 하나.** 감사는 탭해서 거는 링크와 마크업에서 찾은 번호를 모두 나열합니다. 번호가 여럿인 것은 의도일 수 있습니다 (콜트래킹, 지점). 실수라고 부르기 전에 물어보세요. 마크업의 번호는 스마트플레이스와 같아야 합니다.
- **sameAs는 실제 프로필만.** 오늘 있는 스마트플레이스, 소셜, 디렉터리. 없는 프로필이나 남의 프로필로 가는 sameAs는 이 마크업이 해를 끼치는 한 가지 방법입니다.
- **이름 충돌.** 상호가 다른 회사나 보통 명사와 겹치면, 일관된 마크업과 무엇을 어디서 언제부터 하는지를 말하는 소개 페이지가 더 중요합니다. AI 답이 이름을 어떻게 푸는지는 /ai-search 일입니다.
