# 상호작용 마그넷 제작 스펙

퀴즈, 계산기, AI 진단의 제작 모드에서 불러옵니다. 결과물은 퀴즈 도구를 위한 스펙이 아니라 **브라우저에서 여는 작동 앱**입니다. 끝났다는 것은 파일을 열고 모든 경로를 걸었다는 뜻입니다. 각 결과 프로필에 닿고, 공식이 손으로 푼 사례와 맞고, 수집 문이 웹훅 스텁을 호출합니다.

## 대상 형식

- **기본. HTML 한 파일.** `index.html` 하나, 바닐라 JS, CSS 인라인. 빌드 없음, 의존성 없음. Netlify·Vercel에 끌어다 놓거나 아무 사이트에 붙여 배포. `./campaigns/{name}/app/index.html`.
- **Next.js 컴포넌트.** 사용자가 기존 Next.js가 있고 넣겠다고 할 때만. `LeadMagnet{Name}.tsx`(클라이언트)와 `app/api/subscribe/route.ts`. ESP 키는 서버에만.
- **AI 진단**은 LLM 호출을 위해 항상 서버 조각이 필요합니다. HTML 한 파일과 서버리스 함수 템플릿, 또는 Next.js 라우트. LLM이나 ESP 키를 클라이언트에 넣지 않습니다.

디자인. 모바일 먼저, 시스템 글꼴 또는 Google 글꼴 하나, 강조색 하나(있으면 creative-kit.md), 여백, 큰 탭. 한 화면씩, 질문 12개의 벽 아님. 퀴즈는 진행 표시. 스톡 헤더 없음, 이모지 색종이 없음. 이 앱이 브랜드의 첫 제품 경험이고, 유료와 같은 느낌이어야 합니다. `lang="ko"`.

## 퀴즈 뼈대

상태. `intro → question[0..n] → 수집 문 → 결과`. 화면당 질문 하나, 답을 누르면 진행, 뒤로 가면 답이 남음.

```html
<script>
const QUIZ = {
  questions: [
    { text: "...", answers: [
      { label: "...", scores: { profileA: 2, profileB: 0, profileC: 1 } }
    ]}
  ],
  profiles: {
    profileA: { name: "...", headline: "...", description: "...",
                strengths: [], gaps: [],
                cta: { text: "...", url: "..." } }
  }
};
// result = 합이 가장 높은 프로필. 동점은 선언한 우선순위
</script>
```

질문은 7~12. 7 미만은 얇고, 12 초과는 완료가 샙니다. 답은 3~5개. 모든 답이 모든 프로필에 점수(가중)를 줍니다. 하나에만 주지 않습니다.

채점 판단.

- **가중이 통 세기보다 낫습니다.** 실제 사람은 섞여 있습니다. 모든 답이 여러 프로필에 기여하면 분류가 아니라 진단처럼 느껴집니다.
- **모든 프로필이 닿는지 확인.** 프로필마다 가능한 최대를 합합니다. 하나가 절대 못 이기면 균형을 다시. 그다음 프로필마다 답 경로를 클릭해 증명합니다.
- **결과 프로필은 추켜세우되 정직한 진단.** 이름(그들이 주장할 정체), 잘하는 것, 막는 빈칸 2~3, 그 빈칸을 유료에 잇는 버튼. 전환은 프로필 문장에서 일어납니다. 단어를 거기에 쓰고, 인트로에 쓰지 않습니다.
- 질문 문장은 voc.md나 손님의 아픔 말이 있으면 거기서. 손님이 상황을 말하는 방식의 선택지는 "어떻게 알았어요"를 만듭니다.

## 계산기 뼈대

구조. 입력, 실시간 계산, 헤드라인 결과, 막힌 전체 분해.

- **입력.** 최대 3~6칸. 각각 라벨, 현실적인 자리표시, 기본값, 최소·최대. 사람들이 가늠하는 범위(주당 시간)는 슬라이더, 정확히 아는 것(가격)은 숫자.
- **공식.** 진짜 수학, 순수 JS 함수 하나, 각 단계를 평이한 한국어 주석. 지어낸 상수 없음. 모든 계수는 사용자가 말한 사업 논리이거나 제작 중에 물어 받습니다. 가정이 불가피하면 UI에 드러냅니다("월 22영업일 가정").
- **출력.** 큰 헤드라인 숫자 하나, 그다음 해석 구간(X 미만 / X~Y / Y 초과)마다 "당신에게 무슨 뜻인지" 한 문단. 구간 문장이 다리입니다. 가격은 원.
- **문 위치.** 헤드라인 숫자는 막지 않고 보여 줍니다(가치의 증거). 전체 분해, 개인 보고, 받아 둔 사본을 막습니다. 숫자 자체를 막으면 미끼로 읽히고 공유가 죽습니다.
- 출고 전에 손으로 푼 사례 하나와 터무니없는 입력(0, 최대)을 대조합니다.

지역 계산기는 전화와 구·동을 받고, 구·동을 서비스 지역과 대조합니다. 범위는 기본으로 막지 않습니다. `local-magnets.md`.

## AI 진단 뼈대

"URL을 붙이면 점수 있는 해체." 두 조각.

1. **페이지**(HTML 한 파일 또는 컴포넌트). URL 입력, 정직한 로딩("페이지를 보는 중, 약 20초"), 수집 문, 점수 결과. 총점, 차원별 점수, 우선 발견 3개, 버튼.
2. **API 라우트 템플릿** (`api/audit.js` 서버리스 또는 Next.js 라우트).

```js
// POST { url, phone } → { totalScore, dimensions: [{name, score, finding}], topFixes: [] }
// 1. 서버에서 페이지를 가져온다. 200이 아니거나 시간 초과면 분명한 오류
// 2. 아래 RUBRIC으로 구체 증거를 뽑는다. title, h1, 버튼 문구, 분량
// 3. LLM 호출 하나가 증거를 루브릭에 맞춰 채점하고 발견을 쓴다
//    ANTHROPIC_API_KEY=   호스트 환경 변수. 클라이언트에 넣지 않음
// 4. 기본 속도 제한(IP당 예 시간당 5). 호출마다 돈이 든다
const RUBRIC = [
  // 차원 4~6. 각각 무엇을 보는지, 9점 이상, 4점 미만
  // 루브릭이 제품이다. 사용자의 실제 전문가 기준을 인코딩한다.
  // 체크리스트가 있으면 받는다. LLM이 즉흥하게 두지 않는다.
];
```

같은 페이지를 두 번 돌리면 점수가 몇 점 안에 있을 만큼 루브릭이 구체적이어야 합니다. 발견은 그들 페이지를 인용합니다. "헤드라인 '홈페이지에 오신 것을 환영합니다'는 결과를 이름 붙이지 않습니다." 그 구체가 전환 장치 전부이고, 일반 챗봇이 못 흉내 내는 것입니다.

## 수집 문

위치. **질문·입력 뒤, 결과 앞.** 호기심이 가장 큽니다. 노력을 들였고 답까지 칸 하나입니다. 앞에서 막으면 로그인 벽처럼 전환됩니다.

한국 기본은 전화번호 또는 카카오 채널입니다. 메일은 선택 칸이거나, 메일 강의일 때만 필수. 이름 칸을 더하면 가입이 줍니다. 꼭 필요할 때만.

```html
<form id="gate">
  <p>결과가 나왔습니다. 어디로 보내 드릴까요?</p>
  <label><input type="checkbox" required> 견적 연락을 위해 전화번호를 수집하는 데 동의합니다. 목적은 이 결과 안내와 견적 회신, 보유는 상담 종료 후 1년입니다.</label>
  <input type="tel" required placeholder="010-0000-0000" autocomplete="tel">
  <button>결과 보기</button>
</form>
<script>
document.getElementById('gate').addEventListener('submit', async (e) => {
  e.preventDefault();
  const phone = e.target.querySelector('input[type=tel]').value;
  try {
    await subscribe(phone, computeResult());
  } catch (err) { /* 오류를 삼킨다. 결과 표시를 발송 실패에 묶지 않는다 */ }
  showResult();
});
</script>
```

동의 문구의 목적과 보유는 사장님이 확인한 실제여야 합니다. 위 1년은 자리입니다. 개인정보보호법. 조문 번호는 쓰지 않습니다. 의료·금융·대부·건강기능식품 결과를 자동 문장으로 단정하지 않습니다.

세그먼트를 번호와 함께 보냅니다. 결과 프로필이나 점수 구간이 태그되고, `/email-sequences`가 세그먼트별 후속을 쓸 수 있습니다. 그 분류가 상호작용을 만드는 이유의 절반입니다. 광고성 후속은 (광고), 보내는 이, 수신거부, 21시~08시 별도 동의.

## 발송 스텁

배선이 보이고 키 위치가 분명한 함수를 실습니다.

```js
async function subscribe(phone, result) {
  // === 연결 ============================================================
  // 카카오 채널 웹훅 또는 문자 대행사. 키가 있는 서버리스로 ENDPOINT를 둔다.
  // 메일이 두 번째일 때. 스티비, 메일리, Kit, Beehiiv, Loops, Mailchimp.
  // HTML 한 파일의 브라우저에 키를 넣지 않는다.
  // 출시 전에 제공자 문서의 경로를 확인한다.
  // 이 함수는 사장님이 테스트로 한 번 확인하기 전에 라이브 명단에 쏘지 않는다.
  // =====================================================================
  const ENDPOINT = "YOUR_WEBHOOK_OR_FUNCTION_URL";
  await fetch(ENDPOINT, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ phone, segment: result.profileName ?? result.band,
                           source: "{magnet-name}" }),
  });
}
```

브랜드 맥락의 `.env`에 알려진 키가 있으면, 스텁 대신 서버 조각에 실제 호출을 잇겠다고 제안합니다. 자동 발송은 확인 뒤에만.

## 출고 전 QA (하고, 묻지 않음)

조용히 돌리고 `notes.md`에 남깁니다. 넘김은 작동 앱과 README이지 QA 로그가 아닙니다.

1. 브라우저에서 파일을 열거나 개발 서버를 돌립니다. 모든 질문 경로를 클릭해 모든 프로필·구간에 닿습니다.
2. 채점 사례 하나와 공식 사례 하나를 선언된 논리와 손으로 대조합니다.
3. 테스트 번호로 문을 제출합니다. 스텁이 호출되는지(네트워크 또는 콘솔)와, 요청이 실패해도 결과가 렌더되는지 확인합니다.
4. 너비 375px. 가로 스크롤 없음, 탭이 눌림.
5. 결과 문장을 소리 내어 보이스 프로필과 대조합니다.

앱과 함께 캠페인 폴더의 `README.md`. 배포 방법(Netlify·Vercel에 끌기), 키가 어디 가는지, 채점을 깨지 않고 질문·공식·루브릭을 바꾸는 법.
